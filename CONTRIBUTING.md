# Contributing

Short version: **bug reports and feature requests are wanted. Pull requests are
not accepted.** Please read this before you spend an afternoon on a patch.

## Pull requests are not accepted

Not "not yet," and not pending a beta ending. Dashie is a read-and-fork project,
not a collaborative one. Saying that plainly costs less than leaving a
contribution path open that quietly dead-ends.

Two honest reasons:

- **Capacity.** One maintainer. Review is the bottleneck, and an unreviewed PR
  sitting open for months is worse for you than a clear no today.
- **The tree isn't all editable.** Parts of this repo are generated by tooling
  that lives outside it — `dashie-ha-dev/` and the vendored `integration/` trees
  are build output, and some source lives in a private monorepo (see
  [PROVENANCE.md](PROVENANCE.md)). A hand-written patch to the wrong file gets
  clobbered by the next release build rather than merged. A pre-commit hook
  blocks it, which tells you something about how often it happens.

The license is [AGPL-3.0](LICENSE) and that is not decorative: **fork it, run it,
modify it, self-host it.** Those rights are real and permanent. What isn't on
offer is merging your changes back into this tree.

## What genuinely helps

- **Bug reports** — [open an issue](../../issues/new/choose). Real-world HA
  setups are the thing one maintainer cannot manufacture, and reports about them
  are the single most useful thing available.
- **Feature requests**, including "this fights my setup" and "this assumption is
  wrong for me."
- **Design pushback on the docs.** If [PROVENANCE.md](PROVENANCE.md) or
  [PRIVACY.md](PRIVACY.md) doesn't answer a question you actually have, saying so
  is worth more than a patch.
- **Telling us what a patch _would_ say.** An issue that describes the fix, with
  the file and the reasoning, is something that can be acted on immediately — and
  it routes around the generated-tree problem above, because it lands upstream of
  the generator where it belongs.

Integration issues (entities, config flow, pipeline setup) belong in
[dashie-voice-integration](https://github.com/jwlerch78/dashie-voice-integration/issues).

## Response times

Issues are read and triaged — bugs before feature requests. There is no promised
response time. One maintainer with a day job cannot honour an SLA through a busy
fortnight, and a promise nobody keeps is worse than no promise at all.

## Security

Please don't open a public issue for a vulnerability. Email
<hello@dashieapp.com> instead.

## No CLA

There used to be one, alongside a "not accepting code *yet*" policy that implied
it would change. Both are retired. With no contribution path there is nothing for
a CLA to cover, and keeping one around would only suggest a door that isn't
there.
